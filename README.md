# PoladliFX — FinancialJuice → Telegram Alerts

## Что исправлено

1. **Время теперь показывается в Baku (`Asia/Baku`, UTC+4).**
2. **Старые новости больше не отправляются часами позже.**
   RSS используется только за последние 12 минут. В старой версии был `LOOKBACK_MINUTES=180`, поэтому после задержки GitHub Actions бот мог отправлять новости, опубликованные до 3 часов назад.
3. **Фильтр стал строгим:** отправляются только новости с явной пометкой FinancialJuice `RED/HIGH IMPACT` или `ORANGE/MARKET MOVING/MEDIUM IMPACT`. Наличие слов вроде `Fed`, `USD`, `gold` само по себе больше не является причиной для отправки.
4. **В 09:00 по Baku** отправляется отдельный список сегодняшних RED + ORANGE новостей.
5. Workflow запускается примерно **каждые 5 минут**.
6. Добавлена защита от повторной отправки дневного дайджеста в рамках состояния SQLite.

## Важный момент про уведомление за 5 минут

RSS FinancialJuice — это лента опубликованных новостей. Она не является надежным источником будущих `event_time`, поэтому по одному RSS нельзя корректно гарантировать сообщение **ровно за 5 минут до будущего экономического релиза**.

Для настоящего T-5 уведомления нужен источник экономического календаря, который отдает будущие события и их время. Код уже поддерживает опциональный `CALENDAR_JSON_URL` с форматом:

```json
[
  {
    "id": "nfp-2026-09-04",
    "title": "US Nonfarm Payrolls",
    "event_time": "2026-09-04T12:30:00Z",
    "impact": "red"
  }
]
```

Тогда бот при каждом 5-минутном запуске отправит уведомление примерно в T-5.

## GitHub Actions

09:00 Baku = 05:00 UTC, поэтому дневной cron:

```cron
0 5 * * *
```

Пятиминутный polling:

```cron
*/5 * * * *
```

GitHub Actions schedule может стартовать с задержкой. Поэтому 5-минутные breaking alerts имеют небольшое окно допуска, но намеренно не используют 180-минутный lookback.

## Secrets

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- опционально `CALENDAR_JSON_URL`

Не помещайте токены в репозиторий.
